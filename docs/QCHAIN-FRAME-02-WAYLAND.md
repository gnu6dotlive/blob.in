## Proven execution

The original F2→F3→F4 CPU witness, generated by `in.gnu6` on `feat/blobin-qchain-cpu-witness-20261010 @ 4933743`, supplies five bounded 512×384 RGBA8 CPU frames and immutable scene digests.

This checkpoint added a **separate QCHAIN-FRAME-v1 producer and viewer**:

- `crates/blob-frame/examples/qchain_source.rs` — serves exact original CPU F4 buffers on an isolated 0700-parent / 0600 Unix SOCK_SEQPACKET socket; per-connection same-UID / scene SHA / revision / semantic digest / expected pixel SHA validation; sealed single memfd. Five authorized requests, then exits.
- `crates/showcase/src/bin/qchain_viewer.rs` — opt-in `blobin-qchain-viewer` Wayland application. Receives all five sealed memfds; verifies the original CPU receipt; uploads the actual RGBA bytes to **wgpu/Vulkan**; submits each stage on a native 512×384 surface. The shader is only a fullscreen blit, **not a GPU implementation of F2/F3/F4**.
- `scripts/qchain_compositor_gate.py` — independent read-only compositor screenshot oracle; compares original CPU SHA, IPC source/client logs, WGPU submission logs, private screenshots and every RGBA byte, allowing **only** a fixed 18×18 corner-square mask for the compositor's configured 18px rounded corners. Explicit `full_unmasked_frame_pixel_exact:false`.
- `scripts/test_qchain_compositor_gate.py` — five standalone positive/negative laws, including forged centre pixel, pixel immediately outside corner mask and forbidden mask expansion.

## Two live runs, no falsified claims

1. Initial run: all five GPU presentation submissions, **4/5 captures**; initial window activation prevented stage 0 capture, and frames 2–4 had 99.81% exact bytes. Forensics isolated 4×86 mismatched corner pixels and a 12×18 stable extra cursor-like overlay. This run remains **PARTIAL**.
2. Second bounded run: app cursor hidden for this QCHAIN window only, extra overlay disappears; Hyprland `setprop` for this **specific window's** rounding returned success, yet corner pixels remain rounded in screenshots. **All 5/5 captures** obtained while the uniquely matched QCHAIN window was active and visible; source and client processes exited with code 0.
3. The read-only independent oracle `qchain_compositor_gate.py` verifies for **each of 5 stages** that all **195,312 non-corner-masked pixels match the original CPU F4 frame byte-for-byte**; the only differences are the same 86 pixels in each of the four 18px corners. Raw capture bytes are **99.8688%** identical to original (remaining pixels affected by compositor). No image was manipulated to create this verdict.
